FLAGSHIP • SERVERLESS ARCHITECTURE

Pinax

A multi-event registration platform built on AWS with a private frontend, serverless APIs, managed persistence, and infrastructure as code.

Engineering challenge

Build a multi-event platform that handles registration, retrieval, cancellation, persistence, and attendee communication without maintaining traditional application servers.

Engineering solution

CloudFront + private S3 for delivery, API Gateway and Python Lambda functions for the application layer, DynamoDB for event and registration data, SNS/SES for notifications, and AWS SAM for repeatable infrastructure deployment.

Impact & proof

Delivered a working end-to-end registration flow: attendees can register, retrieve and cancel registrations, while records persist in DynamoDB and confirmation notifications are generated. CloudWatch provides operational visibility and GitHub Actions automates backend deployment.

What this proves: I can take a cloud application from architecture to a working, observable serverless system and troubleshoot the integration points between frontend, APIs, compute, data, notifications, and deployment.

TEAM CAPSTONE • HIGH AVAILABILITY + CI/CD

TradeLedger

A cloud deployment for a daily sales and stock-tracking application designed for informal traders and small shop owners, engineered for availability, automated delivery, security, and observability.

Engineering challenge

Move a lightweight business application beyond single-server hosting into an AWS architecture that could remain available, recover from instance failure, deploy changes consistently, and expose useful operational signals.

Engineering solution

CloudFront → ALB → Auto Scaling → EC2 across Availability Zones, with S3, IAM, CloudWatch, AWS Budgets and a GitHub Actions CI/CD workflow supporting the deployment.

Impact & proof

The Auto Scaling Group successfully replaced an unhealthy EC2 instance during testing, demonstrating self-healing behaviour. Automated deployment reduced the manual steps between a code change and the AWS-hosted application.

My contribution: Created and managed the GitHub repository, co-developed the GitHub Actions CI/CD pipeline, contributed hands-on to implementation and deployment, and led the technical documentation.

INDIVIDUAL PROJECT • SERVERLESS APPLICATION

AWS Exam Chatbot

A serverless AWS certification Q&A application that connects a browser-based frontend to managed compute and persistent cloud data.

Engineering challenge

Build an interactive question-and-answer application without maintaining a traditional backend server, while creating a complete request path from the frontend to an API, application logic, persistent data, and operational logs.

Engineering solution

Hosted the frontend on Amazon S3, exposed a REST endpoint through API Gateway, processed questions with Python on AWS Lambda, retrieved matching answers from DynamoDB, and used CloudWatch logging to observe and troubleshoot requests.

Impact & proof

Delivered a working end-to-end serverless application that accepts AWS questions and returns stored answers through the web interface. API testing returned successful HTTP 200 responses, and CloudWatch logs captured function invocation, received questions, and successful matches.

Engineering growth: Configured CORS, moved from broad DynamoDB access toward least-privilege IAM, added structured logging, and attempted a Bedrock enhancement. When model throttling blocked the AI integration, I preserved the working rule-based system rather than destabilizing the application.

AUTOMATION • LINUX + OBSERVABILITY

Web Analytics Pipeline

An automated AWS workflow that turns raw Apache access logs into stored, processed, and visualized traffic data.

Engineering challenge

Move beyond manually inspecting web-server logs by creating a repeatable workflow for collecting, storing, processing, and surfacing operational traffic data.

Engineering solution

Ran Apache on EC2, automated log compression and S3 uploads with Bash and cron, processed stored logs with Python, Pandas and Matplotlib, and surfaced the results through a browser-accessible analytics dashboard with CloudWatch and cost monitoring around the workload.

Impact & proof

Converted raw server activity into an automated analytics workflow. Scheduled log handling reduced repetitive manual work, S3 provided centralized storage, and the generated dashboard made request activity easier to inspect and understand.

What this proves: I can work across Linux administration, scripting, AWS compute and storage, automation, Python data processing, monitoring, and cost awareness rather than treating each skill in isolation.

04 / HOW I THINK

Engineering principles I build around.

01

Secure by default

Prefer least privilege, private origins, scoped access, and intentional network boundaries.

02

Automate repetition

If a process can be validated, deployed, scanned, or collected consistently, automate it.

03

Observe the system

Logs, metrics, and failure signals are part of the architecture, not an afterthought.

04

Document decisions

Good documentation should explain why the system exists, how it works, and what failed along the way.
